# 사진대지 양식 등록·검사

## 이 저장소의 구조

| 파일 | 하는 일 |
| --- | --- |
| `templates/forms.json` | 탭 목록. 양식마다 열 폭·행 높이·사진칸·표 칸 위치가 들어 있다 |
| `templates/*.xlsx` | 실제 양식 파일. 엑셀 출력은 **이 파일을 열어 사진·글자만 채운다** |
| `lib/build.js` | xlsx 생성 |
| `public/app.js` | 화면 미리보기와 PDF. **원본을 변환하는 게 아니라 `forms.json` 숫자로 다시 그린다** |
| `tools/add-form.js` | 양식 파일에서 위 정의를 자동 추출 |
| `tools/check.js` | 검사기 |
| `tools/make.js` | 명령줄로 결과물 만들기 |

**어긋남은 거의 항상 `forms.json` 과 `templates/*.xlsx` 가 서로 다른 모양을 가리켜서 생긴다.**
엑셀은 양식 파일을 그대로 쓰고, 미리보기·PDF는 `forms.json` 을 쓰기 때문에 둘이 어긋나면 화면과 엑셀이 달라진다.

## 새 양식 등록

```bash
# 1. 사용자가 준 통합 문서에서 쓸 시트를 확인한다
node -e "const E=require('exceljs');(async()=>{const wb=new E.Workbook();
  await wb.xlsx.readFile('원본.xlsx'); wb.worksheets.forEach(w=>console.log(w.name));})()"

# 2. 그 시트만 남긴 양식 파일을 templates/ 에 만든다 (숨긴 행이 있으면 반드시 풀어서 확인)
# 3. 자동 인식
node tools/add-form.js templates/새양식.xlsx --name "표시할 탭 이름" --id 아이디 --block 7

# 4. 검사
node tools/check.js 아이디 --pdf
```

`--dry` 를 붙이면 등록하지 않고 인식 결과만 본다.

### 등록 전에 반드시 사람 눈으로 확인할 것

자동 인식이 자주 틀리는 자리다.

- **어느 블록을 베낄지** — 양식에 비슷한 표가 여러 벌 있고, 그중 상당수가 **숨긴 행**이다.
  `ws.getRow(r).hidden` 을 찍어 보고, 사용자가 말한 그 표를 골라야 한다. 잘못 고르면 칸 폭이 통째로 달라진다.
- **예시 글자** — 양식에 견본 값('가배수로 정리', '기초타설' 같은)이 적혀 있는 파일이 많다.
  라벨 바로 뒤 칸은 값칸으로 보게 돼 있지만(`add-form.js` 의 `knownField`), 어긋나면 입력칸이 통째로 사라진다.
  `--file` 검사의 *라벨마다 입력칸 있음* 항목으로 확인한다.
- **글꼴에 따른 열 폭 단위(`pxPerChar`)** — 맑은 고딕 11pt는 8, Arial은 7. 틀리면 사진이 칸을 넘친다.
- **한 페이지에 들어가는 블록 수(`blocksPerPage`, `firstPageBlocks`)** — 첫 장만 머리글 때문에 적게 들어가는 양식이 많다.

## 검사기 (`tools/check.js`)

```bash
node tools/check.js              # 모든 탭
node tools/check.js jangbi       # 한 탭만
node tools/check.js --pdf        # 인쇄 결과까지 (LibreOffice 필요, 느림)
node tools/check.js --file 어떤양식.xlsx    # 아직 등록 안 한 파일 (앱에 올릴 그 파일)
```

**사용자가 "올린 양식이 원본과 다르다"고 하면 먼저 `--file` 로 그 파일을 돌려 본다.**
지금까지 나온 사고는 전부 앱 업로드 경로가 검사기를 안 거쳐서 그대로 나간 것들이다.
`--file` 은 추출한 정의를 원본 통합 문서와 한 칸씩 맞춰 본다 —
열 폭·행 높이·병합 범위·**네 변 테두리**·글자 정렬·화면이 그릴 줄 아는 정렬인지·
입력칸에 견본 값이 박히지 않았는지·라벨마다 값칸이 살아 있는지·수식/날짜가 글자로 새지 않았는지.

검사 항목과 각각이 잡아내는 사고:

1. **정의 ↔ 양식파일** — `forms.json` 의 열 폭·행 높이·표 칸 병합 범위가 xlsx 원본과 같은가.
   *칸 폭이 양식과 다르다* 는 신고는 거의 다 여기서 걸린다.
2. **엑셀 파일 형식** — 다음 일곱 가지가 어긋나면 엑셀이 "손상된 파일"로 보고 빈 시트를 연다.
   인쇄영역 표기(`$$` 금지), 병합 중복, 서식 번호 범위, 행 번호 오름차순,
   페이지 나눔 열 번호(≤16383), 시트 요소 순서, `sheetPr` 자식 요소 순서.
3. **사진 정렬** — 사진이 사진칸 정중앙인가. (두 칸 기준 앵커 `tl`/`br` 을 계산으로 검증)
4. **인쇄 결과(`--pdf`)** — PDF 로 뽑아 실제로 그려진 세로 선 간격을 재고, 정의가 말하는 칸 폭 비율과 맞춰 본다.
   사진칸 바로 아래 표 줄을 찾아 비교한다. 사진칸이 나란한 양식은 두 칸의 표가 한 줄에 인쇄되므로 같은 행을 모두 모아서 비교한다.

전부 통과하면 종료 코드 0.

## 결과물 직접 만들어 보기

```bash
node tools/make.js --list
node tools/make.js --form jangbi --site "양주회천 A-25BL" --date 2026-08-04 \
  --set 업체명="한보건설" --set memo="가배수로 정리" photos/*.jpg
```

## 화면(미리보기·PDF)까지 확인

`scratchpad/serve.js` 가 Vercel 을 흉내 낸다. Playwright 로 탭을 눌러 사진을 넣고
PDF 를 받아 `pdftoppm` 으로 펴서 눈으로 확인하면 된다. 파일 입력은
`setInputFiles` 가 듣지 않으므로 `DataTransfer` 로 넣고 `change` 를 직접 일으킨다.

## 고칠 때

- 정의가 틀렸으면 `forms.json` 을, 양식 파일이 틀렸으면 `templates/*.xlsx` 를 고친다.
  **둘 중 무엇이 원본과 다른지 먼저 정한다.** 원본 통합 문서와 비교하지 않고 고치면 반대로 어긋난다.
- 양식 파일의 병합을 바꿀 때는 그 줄의 모든 칸에 같은 테두리·정렬 서식을 깔고 나서 병합한다.
- 고친 뒤 `node tools/check.js --pdf` 를 다시 돌려 전부 통과하는지 본다.
